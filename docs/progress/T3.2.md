## Findings (Step 0)

### apiRequest and FormData handling
`frontend/lib/api.ts` sets `Content-Type: application/json` **only** when
`typeof fetchOptions.body === "string"`. For `FormData` bodies the branch is
skipped, so the browser sets the boundary-encoded `multipart/form-data` Content-Type
itself. This is exactly correct — manually setting `Content-Type` for `FormData`
would omit the multipart boundary and corrupt the upload.

### CORS configuration (from T2 work, verified in HANDOFF.md)
- `allow_methods` includes `POST` and `DELETE` (added in T2.2f).
- `allow_credentials=True` with `cors_origins=http://localhost:3000`.
- `OriginCheckMiddleware` passes requests with no `Origin` header (D-034).
- Origin check blocks disallowed origins on POST/PUT/PATCH/DELETE with 403.

### Backend API contract (from `backend/app/routers/documents.py` on `t3-upload`)
```
POST   /projects/{project_id}/documents        multipart field "file" → 201 DocumentRead
GET    /projects/{project_id}/documents        ?limit&offset          → list[DocumentRead]
GET    /projects/{project_id}/documents/{id}                          → DocumentRead
DELETE /projects/{project_id}/documents/{id}                          → 204
```

**DocumentRead schema:**
```typescript
{
  id: number;
  project_id: number;
  original_filename: string;
  size_bytes: number;
  page_count: number | null;
  status: string;   // "uploaded" | "processing" | "ready" | "failed"
  created_at: string;  // ISO datetime
}
```

**Error codes from D-031:**
| Code | Meaning | User message |
|------|---------|--------------|
| 409 | Duplicate file in this project | "Already uploaded in this project" |
| 413 | File too large (>20 MiB) | "Larger than 20 MB" |
| 415 | Not a PDF | "Not a PDF" |
| 422 | Corrupt/encrypted/empty/too many pages/project limit | show server detail text |
| 404 | Project or document not found | "Project or document not found" |
| 401 | Not authenticated | redirect to /login |

**No download/preview endpoint** — UI must not offer download or preview links.

### Next.js cacheComponents note (T2.3g lesson)
`next.config.ts` has `cacheComponents: true`. This keeps up to 3 recently
visited routes alive in memory via React `<Activity mode="hidden">`. State
(document list, selected file, upload errors) persists across navigations
unless explicitly cleared in a cleanup effect or on sign-out.
